## What was changed for the sixteenth round (`feat/lodestar` at 920e745, 2026-11-23)

The tasks are the fifteenth's, unchanged (fourteen, eight marks). What the round does differently:

- **The game's state by its class.** The fifteenth round's 17 fields that read 6 and then 2 could not name one
  slot. The leads now carry, under `[statics]`, the design's own name for the game's state (ARCH §6.1) as the
  innermost name of its instance's class; `Namer::static_lead_class` says, from the image's own type information,
  whether a table of methods is that class's. When the pair search is through, the round reads the first word of
  each hit's object (one guarded read each, 64 at most) and marks the hits whose object is of that class
  (`lead`); one such field alone names the slot, and the game's state enters the draft table by the invariant
  recipe as before. The round is given no number from the executable: the study only chose what to check, and it
  showed that the design's name is the class's innermost name (the name itself was already the design's).
- **The lists.** The character search judges first the run at the place the build's layout gives
  (`characters.by_distance`, 0x1F1E8) and lists it as `expected`; a word inside a run of four or more rising
  addresses is tried last. In the fifteenth round such runs used up all 64 candidates.
- **The falls and the moves.** The lists' places go to the likeliest rows first, across all parts: the field that
  fell once and rose once under a bound, then those that rose again, then the rest; of the moves, those that
  ranged like a place. A move carries the class of how far it ranged in the walk, read as a fraction (within 2,
  within 8, within 10,000, further): a place against a direction or an angle. No value is written.
- The report is schema 16 (`lead` on a pair hit, `leads` on the pair search, `expected` on a list, `span` on a
  move).
- **The fake game** keeps a copy of the slot's number in a second object of another class (`--slot-copy`): the
  state case now has three fields that read both numbers, and the class tells the one.
- **Not in this round**: the layout's characters fields read through EldenNet's own reader (the backend has no
  entry that reads the world's group alone yet), and the vitals' fields in the layout. They follow once this
  round has confirmed the list and the health's place again.

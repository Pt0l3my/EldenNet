## What it settled

1. **The finder reproduces R0c.** The pattern, cut again in memory and never written, has 7,151 hits and 7,081
   accepted sites, R0c's own numbers; the image has 11 sections and 235,897 functions, as R0c read; the character
   class's set has 6 classes and the player's 2, both `derived`, the player's two tables of methods among the
   character's six; the task groups' table has 168 entries of 32 bytes with wide names 16 bytes in, and the lead's
   group is at index 110. So what the new report says can be laid beside the old one line for line.
2. **The shape stands at 7,077 places, and every one is accepted.** None is refused for its static's section, its
   class object, its getter or its path: what the pattern hit and then refused (70 of its hits), the shape never hits.
   The count is within the recipe's range, which was left at its widest for this run.
3. **Every site the shape accepts, the pattern accepts too**: 7,077 shared, none accepted by the shape alone.
4. **The pattern accepts 4 sites the shape does not.** This is why the run is "to read first". The report of this
   package gives the count only, not which step of the shape those sites fail.
5. **217 statics, 217 class objects, one getter.** The 217 statics are all aligned to 8; their sites sum to 7,077,
   from 1 to 896 a static; 105 of them have 8 witnesses kept (8 sites or more), 10 have a single site. R0c counted 219 statics
   for the pattern's 7,081 sites and the same 217 class objects, so the 4 sites LIKELY load the 2 statics the shape
   does not reach, through class objects it already knows.
6. **The class objects are no objects with a table of methods.** Of the 217, 110 lie at odd offsets and only 46 at
   offsets aligned to 8, and 54 are one byte from the next. A thing one byte long carries no pointer, so no name
   layout could ever be read from them: this is the cause behind R1's runs 1 and 2 (WHY§206, §207), now in the
   file's own numbers, and it confirms O92's way (the instances' own classes) as the only one.
7. **Every witness is a distinct place inside the image**: 1,231 of them, each the load itself, none listed twice.
   Whether each still decodes to its static is the resolver's check at start, in game.

## What is still open, and what follows

  two things that are no managers. R1's run 3 named the statics by their instances and found 2 of the 219 whose

  package's finder says, for each such site, which step of the shape it fails and how (a load or a test that is not

- **The recipe's range**: once the 4 sites are read, `expect_matches` takes the counted number for this build.
- **The managers' names**: not this run's. The 217 slots are unnamed until the in-game round reads their instances'
  classes (step L5); the table for 2.7.2.0 is written then, with these witnesses.
